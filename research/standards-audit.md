Link any PR it waits for. Draft only while unfinished. Review the diff against the list in "Before opening" and run the checks each `## This repository` lists.

## 3. RFC and maintainer pre-discussion

- **No RFC is needed by the written rules.** Nothing in `standards/` or the accepted RFCs requires an RFC for a new craft-libs crate or new file-format support. Recent crates (craft-cdr, ppt-binary, sbs, ipp, color-transform) arrived as ordinary PRs linked to extraction issues. New dependencies need an RFC only when the licence is off the allowlist; none are added here.
- **RFC-0009 (shared infrastructure admission) is an open draft.** If it merges before our PRs, it applies: two consumers by default, or an approved exception, and a named responsible maintainer. Ask in the umbrella issue before opening L1 which way maintainers read it for a layout crate with one consumer. Mermaid and VSDX fit the "standard file format parser" exception more easily than layout does. Possible fallback if refused: keep `craft-graph-layout` inside FigCraft (`crates/layout`-style L2 crate) and move it later when a second app needs it. This is the one structural decision the user should make, since it changes where the code lives.
- **Open question for maintainers, not blocking:** whether built-in shape libraries and VSSX loading should be FigCraft-only, or later share a stencil model in craft-libs (RFC-0030 shared-vector layer is in flight; PR #2260 is open). Raise in the figcraft umbrella issue, not in a PR.
- **Naming:** "Mermaid", "VSDX", "VSSX" and "UML" are language or format names (naming.md 3). No rule 4 trademark check is required for them. If "Diagram" or any shape-library name is later proposed as a feature label, it needs rule 4 (note SmartArt is on the names list with "Diagram" as the replacement, so "Diagram" is the established name).
- **Not needed:** a claims comment today (live-claim rules start when a claim exists; the user has said not to claim). The first claim will be the umbrella issue or the first PR's `Part of #N`.
